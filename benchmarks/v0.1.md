# laya-apple v0.1 benchmark report

**Scope.** Warm single-request latency of the v0.1 runtime for all three checkpoints on
MLX (GPU), the Core ML ANE artifacts, and `device="auto"`, measured through the product
(`laya-apple benchmark`). It also covers load and cold-start costs and the parity status of
every offered artifact. Concurrency is v0.2 and is not covered here.

## Setup

| | |
|---|---|
| Hardware | Apple M4 Max (16 CPU cores: 12P + 4E), 64 GB |
| OS | macOS 26.6.2 (25G83), AC power, no thermal or performance warnings recorded |
| Software | Python 3.12.14, MLX 0.32.2, coremltools 9.0, NumPy 2.1.3, laya-apple 0.1.0 |
| Checkpoints | pinned revisions and weight hashes (`docs/support-matrix.md`) |
| ANE artifacts | `bc1s-masked`, B=1, FP16, `CPU_AND_NE`, built and validated on this machine by `laya-apple artifacts build` |

**Method.**
- Driver: `scripts/release_bench.py`. It runs 50 configurations (model × device × exact
  length × question count), each in a fresh `laya-apple benchmark` process.
- Each configuration: 10 warm-up iterations, then 50 timed iterations at each of two
  boundaries:
  - **forward:** the backend call only, synchronised;
  - **predict:** end to end, covering prompt build, routing, forward and answer formatting.
- Two passes, the second in reverse order. The table reports the mean of the two pass
  P50s and the larger of the two P99s. "Pass Δ" is the pass-to-pass change of the forward
  P50.
- Requests are exact-length: the longest prompt row is exactly L tokens (`laya_apple.workload`).
- Raw records with every sample: `benchmarks/v0.1/raw.jsonl`.
- Tables: `scripts/bench_report.py benchmarks/v0.1/raw.jsonl`.

## Results

100 of 100 records ok. Every `auto` configuration ran on the device the v0.1 rule
prescribes, with the expected routing reason. Pass-to-pass differences of the forward P50
are within ±2.4%, except multilingual ANE L64 at −3.7% (0.13 ms on 3.4 ms).

## Against the v0.1 expectations

Expected: Phase -1 model-only P50, ±5%.

| Model | MLX L128 (expected → measured) | MLX at max_len | ANE L128 |
|---|---|---|---|
| laya | 12.27 → 12.27 (0.0%) | 35.22 → 35.26 (L512, +0.1%) | 9.86 → 9.89 (+0.3%) |
| laya-multilingual | 6.47 → 6.46 (−0.2%) | 29.11 → 29.27 (+0.5%) | 4.31 → 4.31 (0.0%) |
| laya-typed-decisions | 12.23 → 12.26 (+0.2%) | 71.00 → 71.02 (+0.0%) | 9.93 → 9.88 (−0.5%) |

- All nine values are within ±0.5% of Phase -1.
- End-to-end overhead (predict − forward P50) is 0.02–0.76 ms, within the ≤ 1 ms target.
  It grows with length, mostly from tokenising the context.
- `auto` pays no measurable cost over the device it selects.
- Where auto uses the ANE, it is 1.15–1.63× faster than MLX at the same length.
- The one explicit-only bucket (multilingual L256) is 1.9% faster than MLX when measured
  exactly at 256 (8.34 vs 8.50 ms). Auto still does not use it: a request just above 128
  would pay the full L256 cost on the ANE but only about 6.4 ms on MLX (§7.2).

## Load and cold start

`Laya.from_pretrained`, warm caches, fresh process:

| Model | device="gpu" | device="ane" / "auto" |
|---|---:|---:|
| laya | 0.15 s | 1.48 / 1.54 s (3 buckets + MLX for auto) |
| laya-multilingual | 0.39 s | 1.65 / 1.60 s (4 / 3 buckets) |
| laya-typed-decisions | 0.15 s | 1.48 / 1.55 s (3 buckets) |

- Per-bucket ANE artifact load with a valid verification stamp: 0.14–0.31 s.
- The first bucket in a process adds about 1.1 s for importing coremltools.
- Release gate item 4 (≤ 1 s per artifact load from the cache) holds.

One-time costs:
- **First load after verification changes.** The file hash and compute-plan check run on
  the first load, and again whenever the artifact files, macOS build or coremltools
  change: about 1.1 s per bucket.
- **First load at a new location.** Core ML compiles for the ANE on the first load of an
  artifact location: 25–86 s per bucket, measured during this release. `artifacts build`
  pays this once at the registered path. If the system evicts its cache, the next load
  pays it again.
- **Build.** `artifacts build` takes 59–120 s per bucket, covering conversion,
  compilation, placement and the parity gate. It then pre-warms the registered path in
  40–86 s. The ModernBERT-large buckets take about twice as long as the mmBERT-base ones.

  rebuilt artifacts.
