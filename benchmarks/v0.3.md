# laya-apple v0.3 benchmark report — production hardening

**Scope.** Four things measured through the product API, on the tested profile:
- sustained load: stability, memory and thermal behaviour;
- cold start (`ane_startup="wait"` against `"background"`);
- the runtime placement probe;
- reproducibility of the shipped routing table by `laya-apple calibrate`.

Single-request latency is unchanged from v0.1 (`benchmarks/v0.1.md`). Concurrent
throughput is unchanged from v0.2 (`benchmarks/v0.2.md`).

## Setup

- **Hardware and software:** Apple M4 Max, macOS 26.6.2 (25G83), Python 3.12.14, MLX
  0.32.2, coremltools 9.0, laya-apple 0.3.0. Artifacts are the registered v0.1 builds.
- **Machine state:** quiet apart from the run itself. No thermal or performance warning
  was recorded by `pmset -g therm` before or after the soak.

## Sustained mixed load (600 s)

`LAYA_APPLE_STRESS=1 LAYA_APPLE_STRESS_SECONDS=600 pytest tests/stress`. Raw data is in
`benchmarks/v0.3/sustained-mixed-load-600s.json`.

**Setup:**
- Model `laya-typed-decisions`, `execution="workers"`, `device="auto"`.
- Six client threads, each cycling through three request types:
  - short: L128, one question;
  - long: L1024, one question;
  - multi: L96, three questions.
- Every answer is compared with the inline answer from the device that served it.

| Metric | Result |
|---|---|
| Requests completed | 19,202 (32 req/s, closed loop) |
| Errors / answer mismatches | 0 / 0 |
| Served | short on ANE 6,399 (3 on GPU for `ane_backlog_shorter_on_gpu`), long on GPU 6,402, multi on GPU 6,398 |
| Short-request P99, first third vs last third of the run | 10.90 ms → 10.84 ms (no drift) |
| Parent + worker RSS growth over the run | +6.0 MB |
| Thermal / performance warnings | none |

The same suite also passes three shorter checks:

| Test | Setup | Criterion |

## Cold start

`scripts/bench_coldstart.py`, raw data in `benchmarks/v0.3/coldstart.json`.

**Method:**
- Core ML caches its on-device ANE compile per artifact location. To measure a genuinely
  cold start, each run copies the registered artifacts to a fresh cache location and starts
  a new process.
- `execution="workers"`, `device="auto"`. The ANE worker loads every offered bucket (the
  auto buckets plus the tie band), with full verification: file hash, compute plan and
  placement probe.
- Warm start is the same process opening the model again at the now-compiled location.

| Model | Buckets | `wait`: from_pretrained returns | `background`: from_pretrained returns | `background`: first request | `background`: ANE ready | Warm start, `wait` / `background` |
|---|---|---:|---:|---:|---:|---:|
| laya-typed-decisions | 64, 96, 128 | 298.9 s | 1.35 s | 17.8 ms on GPU (`ane_starting`) | 271.6 s | 1.87 s / 0.58 s |
| laya | 64, 96, 128 | 276.8 s | 1.33 s | 18.2 ms on GPU (`ane_starting`) | 269.8 s | 1.87 s / 0.76 s |
| laya-multilingual | 64, 96, 128, 256 | 177.0 s | 1.42 s | 10.7 ms on GPU (`ane_starting`) | 176.7 s | 2.71 s / 0.41 s |

- **Cold.** With `wait`, a fresh artifact location costs 3–5 minutes before the first
  request, almost all of it Core ML's on-device ANE compile. With `background`, the model
  serves on MLX within 1.4 s. The ANE joins when its compile finishes, and every request
  after that went to the ANE (`after_ready_device`).
- **Different answers are expected.** In `background` mode the first request (MLX) and the
  later one (ANE) run on different devices, so their answers agree only within the parity
  tolerance. This is the `same_answers: false` in the raw data. Answers from the same
  device are bit-identical.
- **Warm.** Once compiled, a restart takes 1.9–2.7 s with `wait` and 0.4–0.8 s with
  `background`.
- **Avoiding the cold cost.** `laya-apple artifacts build` and `artifacts import` pre-warm
  the registered location, so users normally meet only the warm figures. If the system
  evicts its compile cache, `laya-apple artifacts warm MODEL` pays it again ahead of
  traffic.

## Runtime placement probe

`scripts/bench_probe.py`, raw data in `benchmarks/v1.0/probe.json`.

**Method:** for each artifact, the fastest of 5 Core ML predictions is measured with the
model as the runtime loads it (`CPU_AND_NE`), and with the same artifact on `CPU_ONLY`. The
pair is taken three times.

| Model | Bucket | Loaded (ANE), ms | `CPU_ONLY`, ms | Ratio, worst of 3 |
|---|---:|---:|---:|---:|
| laya | 64 | 7.90–7.99 | 16.14–16.21 | 0.495 |
| laya | 96 | 8.57–8.73 | 24.54–24.65 | 0.356 |
| laya | 128 | 9.28–9.34 | 26.75–26.88 | 0.349 |
| laya-multilingual | 64 | 3.15–3.30 | 7.61–7.65 | 0.433 |
| laya-multilingual | 96 | 3.65–3.66 | 11.33–11.41 | 0.323 |
| laya-multilingual | 128 | 3.87–3.98 | 12.14–12.39 | 0.328 |
| laya-multilingual | 256 | 7.63–7.69 | 24.03–24.14 | 0.320 |
| laya-typed-decisions | 64 | 7.86–7.92 | 16.13–16.21 | 0.491 |
| laya-typed-decisions | 96 | 8.58–8.70 | 24.54–24.60 | 0.355 |
| laya-typed-decisions | 128 | 9.36–9.43 | 26.75–26.81 | 0.353 |

- **Why 0.8.** The worst ANE ratio is 0.495. A model that Core ML runs on the CPU measures
  about 1.0. The threshold `PROBE_MAX_RATIO = 0.8` leaves margin on both sides.
- **Load-independent.** Both timings are taken back to back on the same input, so machine
  load affects them alike.
- **Cost:** 0.10–0.19 s per bucket to load the `CPU_ONLY` instance, plus 12 predictions.

## Calibration reproduces the shipped routing table

`laya-apple --offline calibrate` was run for all three models on the tested profile. The
local profile is kept as `benchmarks/v0.3/calibrate-profile.json`.

**Method:**
- MLX is measured at q = 1, 4 and 8 over the lengths up to `max_len`, and the ANE at each
  offered bucket.
- Each point is the P50 of 30 synchronised backend forwards after 5 warm-up runs.
- The same derivation rule as the shipped table (`laya_apple/derivation.py`) is applied.

| Model | Bucket | ANE, shipped → calibrated (ms) | MLX q1, shipped → calibrated (ms) |
|---|---:|---:|---:|
| laya | 64 | 8.10 → 8.08 | 9.40 → 9.41 |
| laya | 96 | 9.00 → 9.05 | 11.59 → 11.40 |
| laya | 128 | 9.86 → 9.82 | 12.27 → 12.23 |
| laya-multilingual | 64 | 3.43 → 3.40 | 5.42 → 5.39 |
| laya-multilingual | 96 | 3.85 → 3.86 | 6.36 → 6.29 |
| laya-multilingual | 128 | 4.31 → 4.29 | 6.47 → 6.46 |
| laya-multilingual | 256 | 8.35 → 8.36 | 8.56 → 8.59 |
| laya-typed-decisions | 64 | 8.07 → 8.11 | 9.39 → 9.35 |
| laya-typed-decisions | 96 | 9.02 → 9.01 | 11.57 → 11.61 |
| laya-typed-decisions | 128 | 9.93 → 9.95 | 12.23 → 12.26 |

- **Every point is within ±1.7% of the Phase -1 value** that the shipped table was
  derived from.
- **The derived auto buckets equal the shipped ones:** 64 / 96 / 128 for all three
  models, with `auto_ane_max_len` 128 and one question.
- multilingual L256 is again inside the tie band (ANE 8.36 ms against MLX 8.59 ms), so it
  stays explicit-only.
- On this profile the shipped table is used, and the local profile is ignored.
- On an unvalidated machine, the same command produces that machine's table.
